FAQ

Questions, answered.

Will it slow down my app, or break it if EZLogs is down?

It’s built not to. On a normal server, events are buffered in memory and sent in the background, outside your request. On serverless hosts (Vercel, Lambda, Netlify) they are sent as each request finishes: after the response where the host allows it, otherwise within a 2-second limit, so a slow EZLogs never holds a request for longer than that. If EZLogs is unreachable your app keeps running: the agent retries each batch a few times, then drops it, and never holds more than 10,000 events in memory. Delivery is best-effort, and it never throws an error into your app.

How is this different from Datadog, Sentry or New Relic?

Those tools tell engineers whether the system is healthy: errors, traces, metrics. EZLogs tells everyone what happened: which customer, which agent, which booking or order, in one sentence. Keep your monitoring; EZLogs sits next to it.

What data do you store, and where?

The events your app sends: request paths and parsed parameters, job names and arguments, and database values (what changed, a new record’s values and, on Next.js, a deleted record’s last values). Raw request and response bodies are not sent. Anything named like a password, token, secret, API key or card number is masked or dropped inside your app before it is sent, and you can add your own patterns. Data is stored on Hetzner servers in Finland (EU), with encrypted backups in the Netherlands (EU). Self-hosting is not available yet. Security details.

Which frameworks work today?

Ruby on Rails: requests, Sidekiq and ActiveJob jobs, ActiveRecord changes and bulk SQL (update_all, delete_all…), all on their own. Next.js: routes, Server Actions and page views when the app has a middleware.ts (or proxy.ts); database changes through Postgres triggers (one command) plus a one-line wrapper for Prisma or postgres.js; background jobs with BullMQ and Upstash Workflow / QStash on their own; Inngest v4 too; Inngest v3, Trigger.dev and Supabase Queues with a short addition.

Does AI write the logs?

No. Cards, titles and timelines are built from your events by fixed rules, so the same events always give the same card. AI is optional: it can add a plain-English explanation to an action, answer chat questions, and match a pinned question to a check you confirm. It only works from events your app actually sent, and you never need it to read a card.

Can I export my data?

Yes. Company admins can download a full JSON export of their actions at any time, and signed audit exports for any date range (up to 50,000 actions per file).
