EZLogs for Lovable, Bolt and v0

See what people do in your Lovable app, in plain English.

You built the app with an AI. Now people use it, and you can’t see what they do. EZLogs shows every change, sign-up, sign-in and file, who did it, and what failed for them, as one sentence per action: “Dana created the task ‘Launch plan’”, “Someone tried to sign in but it failed (wrong email or password)”. Anyone on your team can read it.

What you see

  • Every change to your data, with who made it: a task created, a status moved from “doing” to “done”, a record deleted, each value before and after. Tables named like secrets (api_keys, payment_tokens) are left out, and very large values show their size.
  • Sign-ups, email confirmations and sign-ins.
  • Files uploaded, replaced and deleted (never the file itself).
  • Background work your database runs on a schedule, marked as the system.

With the browser part (step 3 below), also:

  • What failed for people, with the reason: a save refused because it already exists, a wrong password, a file too large, a password too weak.
  • Sign-outs.
  • One action per click: everything one click changed reads as one action.

Install in a few minutes

  1. Sign up, then open Settings → API keys → Lovable · Bolt · v0 and click Create install code.
  2. Paste the install code into your project’s SQL editor and press Run. In Lovable: More → Database → Manage → SQL editor. In Bolt or v0: the Supabase dashboard → SQL Editor (a Bolt Database is first claimed into your Supabase account: Bolt → Database → Claim). From then on, your database records every change and sends it to EZLogs.
  3. Paste the prompt from the same page into your AI builder’s chat, then publish. It adds a small open-source package that reports the calls that fail in people’s browsers.
  4. Use your app. Actions appear in your Timeline within seconds.

Building several apps? Add each one on the same page: every app gets its own code and prompt, and its own project in your Timeline.

What it never does

  • No login token, email or password leaves the browser. The browser package never sends those, an error message or what someone typed. It sends a failed call’s method, table, status and error code, and the session id that lets EZLogs name the person from your own database.
  • Never changes your data. The install adds its own ezlogs schema to your database; EZLogs itself never connects to your app or your database. It only receives what your database sends.
  • No secrets. Columns named like passwords, tokens, secrets, API keys or card numbers never leave your database. Password hashes and login tokens stay out.
  • Light, and never breaks your app. Each change adds a small write inside your database and never makes a save fail. If EZLogs can’t be reached, your app works the same and changes wait in your database (up to 7 days) until they can be sent. Nothing runs while your app is idle, so a Lovable project still pauses.
  • No tracking by default. It records what people do, not what they look at. Page views are a switch you turn on per app: only for signed-in people, named by your app’s own routes, never the address as typed.

Both parts are open source, so you (or your AI) can read every line first: the database install and the browser package. To remove it: run select ezlogs.uninstall(); in the SQL editor, and ask your AI builder to remove @ezlogs/browser and the EZLogs section of AGENTS.md.
